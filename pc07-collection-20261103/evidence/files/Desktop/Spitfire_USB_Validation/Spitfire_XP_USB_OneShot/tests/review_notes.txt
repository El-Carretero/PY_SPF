Independent package review, 2026-11-01 UTC

Scope
Reviewed runner.js and native UI/capture sources. No physical PC access or laser
operation was performed by this review. Mock tests do not substitute for XP
execution or physical-controller field validation.

Corrected findings during review
1. Completion originally depended only on absence of a runner error. The root
   implementation now also rejects a missing final capture summary, nonzero
   capture exit, capture errors, missing directions and incomplete action plan.
2. A menu-item click originally verified a popup before an 80 ms cursor delay.
   The UI implementation now rechecks main identity/geometry/origin and the exact
   visible popup immediately before input, rejecting other same-process panels.
3. Known CVI runtime identity was originally required only for auxiliary close.
   It is now required before all automatic UI input.
4. Initial service mode originally repeated the same screens twice. The runner
   now performs one five-screen pass while preserving initial service access.
5. UI stop path and capture stop path are now coordinated explicitly.

Automated checks
node tests/test_runner.js: 16 mocked orchestration tests passed after these fixes.
Cases include normal-user restore, initial service mode, missing/failed/existing
incompatible driver, Opt-out OFF, absent app, missing bidirectional traffic,
observed setting command, UI guard failure, early/final capture failure, missing
summary, capture IO error, missing reply count and explicit cancellation.
These mocks verify control flow, not ActiveX/WinPcap/GUI behavior on Windows XP.

Source review observations
- UI has no networking, process launch, process-memory-write or arbitrary-input
  interface. Only fixed reviewed display/navigation operations are exposed.
- Original launch/exit/restart and connection-warning acknowledgement are absent.
- Opt-out, access level and connection hold state are read from the identified
  original image; Opt-out OFF blocks automated UI rather than changing it.
- Main executable, UIR resource and loaded CVI runtime file identities are gated.
- Only recognized auxiliary panels have close dispatch; original main is not
  closed. Initially visible panels are preserved.
- Mouse/key input checks cancellation, capture proof freshness and target state.
- Capture uses WinPcap receive APIs, nonpromiscuous mode, and classic Ethernet
  PCAP output. Its x86 cdecl ABI declarations match WinPcap structures.
- The packet observer latches setting-tag/malformed/ambiguity/drop errors before
  further automatic input. It is not a firewall and cannot prevent a command
  already transmitted by the original application or another actor.
- UDP port 1024 is the configured capture scope. Readiness decoding requires
  complete unfragmented IPv4 Ethernet frames and a unique recent reverse pair.
  This is not a claim to capture arbitrary protocols on the PC.
- Native screenshot and packet timestamps use the XP clock; clock accuracy is
  not synchronized or guaranteed by the package.

Remaining validation boundary
The installed driver, actual XP GUI timing and packet-file reopening must be
validated in the isolated p07 VM. Physical controller response semantics and the
physical original PC's hardware/driver compatibility remain field-test matters.
