SPITFIRE XP UI CONTROLLER — CURRENT MODE, MOUSE-ONLY

Use the package launcher for the complete capture/test. This executable is the
native UI component. It attaches to an ALREADY RUNNING original program; it never
starts, exits or restarts the original, acknowledges connection warnings, or sends
network traffic. It is a Windows-subsystem executable and creates no console.

Supported internal commands:
  bin\readonly_ui.exe preflight NEW_OUTPUT_DIRECTORY
  bin\readonly_ui.exe temperature NEW_OUTPUT_DIRECTORY PROOF_FILE STOP_FILE
  bin\readonly_ui.exe timing NEW_OUTPUT_DIRECTORY PROOF_FILE STOP_FILE
  bin\readonly_ui.exe faults NEW_OUTPUT_DIRECTORY PROOF_FILE STOP_FILE
  bin\readonly_ui.exe setup NEW_OUTPUT_DIRECTORY PROOF_FILE STOP_FILE
  bin\readonly_ui.exe about NEW_OUTPUT_DIRECTORY PROOF_FILE STOP_FILE

All directories must be new, use the XP active code page and fit MAX_PATH.
There are no regensvc/user verbs and no keyboard input implementation. The initial
user/service access level is retained. If the operator already uses service mode,
the same reviewed menus capture its larger panels. This tool does not switch modes.

In user mode with Empower Opt-out ON, original menu item5 (Empower Setup) is
explicitly disabled by _check_if_system_healthy. The setup step therefore returns0
with result.skipped=true and skip_reason="disabledOptoutuser", BEFORE any input.

BEFORE FOREGROUND OR MOUSE INPUT
Only the exact main895x550 CVI window may initially be visible. Known offscreen
CVI framework windows are ignored. Other original panels, popups, text editors,
carets or held keys/buttons cause capture-only/stop. Nothing is cleared or dismissed.
The guard reads the validated CVI Window->generic Panel->public wrapper chain,
including HWND/back-reference/type/runtime/main-global identity checks. It maps
remembered selector kind3 to nativeID=selection_value+1, then to a unique public
control through the checked CVI list. Only no active/remembered control or the
known closed plain Motor Speed ring(public3) permits mouse-only navigation.
A remembered numeric or unknown control blocks input even if its active flag is0.
No letters, arrows, Enter, Escape, Space or other keyboard events are sent to a ring.
Access level must remain the initial value. Input timestamps and held inputs are
rechecked immediately before foreground changes and mouse-down after other checks.

ALLOWED ACTIONS
Fixed View menu headings/items open Temperature, Timing and High Voltage, Active
Faults, and (when enabled) Empower Setup. Help > About opens Help. Popup class/PID,
geometry, frozen main client origin and exact hit-test ownership are rechecked
immediately before the item click. No parameter-panel control is clicked or edited.

A newly opened exact auxiliary HWND is captured and then hidden only if no external
input occurred since the helper's own menu-item mouse-up. GetLastInputInfo must
match the recorded timestamp, including a final comparison immediately before
close. Other panels or input stop the sequence and leave the current screen alone.
Before any foreground change and again before the menu-item click, the target
must already be uniquely hidden and bound through its CVI wrapper to the original
panel global. Its generic-panel fields0x44 and0x48 must both be0, confirming no
active editing context. A remembered numeric selector alone is allowed for that
inactive hidden target. The opened HWND must equal the verified hidden HWND.
Only reviewed auxiliary close_ctrl callbacks are used:
  Temperature6 -> close_ecu; Timing21 -> close_info; Faults33 -> close_fault;
  Setup12 -> close_setup; Help9 -> close_help.
They solely HidePanel. SC_CLOSE is never sent to the main window or a Warning.
Original show-panel OPEN flags remain set after HidePanel, so original polling may
stay expanded. The helper never edits those internal flags.

EXCLUDED
Original startup/exit/restart and connection Warning OK (startup/retry can send
EMP:LBOBREAK1 automatically), all Laser/RUN/STOP/HV/motor/TEC controls, parameter
fields/sliders, Opt-out changes, fault reset, interlock/override controls, console,
access-mode switching, Escape and every unreviewed button. No arbitrary click API.

OUTPUT
UTC guest-clock timeline.jsonl, before/after BMP screenshots and window inventories,
process inventory, original-state JSON, skipped.jsonl and context-NNN.json evidence
for every context guard. Preflight additionally records read-only CVI focus/mapping
and bounded raw diagnostic data. It does not alter focus or issue input.
result.json contains exit_code, original_pid, emp_optout, gAccessLevel,
preflight_ready, preflight_reason, context_reason, skipped, skip_reason,
keyboard_input_implemented:false and original_left_running.
Stable reason codes include original_missing, identity_mismatch, optout_off,
connection_warning, initial_auxiliary_open, editable_or_unknown_focus,
original_popup_open and external_input_detected.

CAPTURE COORDINATION
The launcher publishes exactly these seven proof lines with decimal values:
  schema=spitfire-passive-v1
  ui_ready=1
  write_commands=0
  observed_pairs=1
  updated_tick=123456
  original_pid=123
  initial_access=0
updated_tick must come from live native passive-capture status, not the launcher
clock. Proof age must remain<=5000ms. PID and initial access must match. Missing or
incomplete replacement reads get up to3 attempts20ms apart; malformed/stale proofs
never use a cached success. This is a coordination guard, not an authenticated token.
The native reader takes a bounded4096-byte snapshot with read/write/delete sharing,
then closes its input handle before parsing or writing evidence. Atomic publication
can therefore replace the proof while the prior immutable snapshot is inspected.

Atomic publisher:
  bin\proof_publish.exe C:\run-folder\proof.tmp C:\run-folder\proof.txt
Only absolute drive paths, those filenames and the same parent are accepted.
MoveFileEx(REPLACE_EXISTING|WRITE_THROUGH) never deletes the old proof first.
Exit0=published; exit1=sharing/lock conflict after up to3 attempts20ms apart;
exit2=invalid input/source or another failure. XP access-denied errors get the same
bounded retries, but persistent denial returns2. No ACLs are changed.

CANCELLATION
The launcher stop file and held F12 stop subsequent input. A mouse-down already
sent is followed by its own release; a failed release gets one release-only retry.
Cancellation never sends Escape, OFF, warning OK or another device command. Original
stays running. Do not interact with the original during the sequence. A passive
monitor cannot retract a command independently sent by the original or an operator.
