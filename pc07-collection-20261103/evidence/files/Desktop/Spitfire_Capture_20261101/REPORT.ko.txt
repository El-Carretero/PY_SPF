2. Opt-out 확인과 실제 실행
기존 응답 출처:
C:\Users\Fluke\Desktop\Spitfire_LogAudit_20261030\reply-values.json

초기 부트스트랩은 VMware Tools 부재와 호스트 입력 미전달로 사용자에게 실행을 요청했다. 원격 HTA의 바이너리 저장 제한 및 래퍼 코드의 닫는 태그 오류를 수정한 후 세 번째 수동 호출에서 성공했다. 실제 점검은 XP 내부에서 자동 실행되었다. OS 보안 설정은 바꾸지 않았다. 실행한 HTA의 원본과 SHA-256은 원시 증빙에 보존했다.

5. 조사한 컨트롤과 건너뛴 동작
control_review.json 및 reviewed-controls.csv는 기존 원본 바이너리 분석 자료에서 검토한 메뉴 6개와 콜백 컨트롤 89개의 정적 허용/제외 목록이다. 현 게스트 원본 UI를 실행해 확인한 목록과 구별해야 한다. 현재 원본 UI 실측과 클릭 실행은 모두 미실행이다.

정적 검토상 후보: About, Temperature Control, Timing and High Voltage, Active Faults 표시, Empower Setup 표시, 확인된 CLOSE/HIDE, UI Exit. regensvc는 표시 전환 후보이며 미실행.
건너뜀: 원본 시작/안정화/메뉴 탐색/조회/도움말/종료/재시작 전체(Opt-out ON 조건 미충족).
항상 제외: RUN/ON/OFF/STOP, HV, 모든 파라미터·모드·Opt-out 변경, fault reset, interlock/humidity override, motor, calibration, manual SEND, 용도 불명 컨트롤.
Escape도 단순 창 닫기가 아니라 OFF 명령 경로로 분석되어 사용하지 않았다.
정적 분석상 원본 시작은 EMP:LBOBREAK 1을 자동으로 큐에 넣고, 특정 응답은 모드 변경/RES12를 자동 유발한다. 이는 이번 캡처에서 관찰한 패킷이 아니다. 후속 원본 시험은 자동 명령도 기록하면서 적용하지 않는 별도 시뮬레이터와 현재 UI 컨트롤 검증이 필요하다.

6. 확인 범위와 미확인 사항
확인됨: XP 내부 실행파일 동작, 게스트/호스트 격리 조건, 기존 시뮬레이터 Opt-out=0의 실제 조회, 양방향 진단 패킷 수집·변환·재열기, 타임라인·화면 보존, 임시 호스트 규칙/리스너 정리.
미확인: Opt-out ON 원본 프로그램의 실제 시작 패킷/폴링 주기/화면별 조회/재시작 동작, 원본 UI의 현재 Opt-out 표시, 원본 프로그램 전체 화면 자동화의 실행 성능, 실물 컨트롤러의 응답 의미/상태 전이/타이밍, 레이저의 실제 상태.
시뮬레이터 응답을 실물 제어기의 동작으로 해석할 수 없다. 주기 통신 요약은 이번 실행에 해당하지 않는다(단발 조회 1회).

7. 결과물과 재실행
README.ko.txt에 실행 절차. guest_probe.exe는 XP 호환 native x86이며 Python 설치가 필요 없다.
Run-Preflight.ps1은 재실행용 호스트 통합 스크립트로 구문 검증했고, 본 실행에서는 구성 모듈을 단계별로 실행했다. 통합 스크립트 전체를 두 번째로 실행하지 않았다.
전체 원본 화면 순회 자동화는 구현/실행 완료 상태가 아니다. 현재 허용 조건에서 완료된 결과는 안전한 사전 점검·캡처 인프라와 차단 증빙이다.
원본 Opt-out 조건을 임의로 변경하지 않은 채 이 상태를 보고한다.

최종 상태: XP VM은 켜진 상태로 두었고 진단 결과 창이 남아 있다. 원본 프로그램은 시작하지 않았다. p07의 UDP1024/HTTP18978 리스너0, 이번 임시 방화벽 규칙0, Pktmon 비활성 및 필터 없음으로 최종 재확인했다. 게스트/실물 레이저 설정을 변경하지 않았다.
