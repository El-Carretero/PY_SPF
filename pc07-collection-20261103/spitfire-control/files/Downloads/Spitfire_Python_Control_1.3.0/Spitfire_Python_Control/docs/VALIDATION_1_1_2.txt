Spitfire Python Control 1.1.2 — 개발 환경 검증 기록

환경: Python 3.12.14, Linux. 실제 Windows 및 실제 장비는 이용하지 않았다.
이 실행 환경에는 GUI 표시 서버가 없어 새 GUI 검증 worker의 성공 경로를 실제 실행하지 못했다.
이전 1.1.1 GUI 검증 기록은 그 버전의 기록이며 이번 버전의 Windows 실행 증거로 사용하지 않는다.

자동 회귀 검사:
- 95개 발견: 85개 통과, 실패 0, 오류 0, Tk display가 필요한 10개 skip
- 추가 validation 테스트 24개 통과
- Windows exclusive UDP bind 옵션은 mock으로 확인했으며 실제 Windows OS 검증은 아님
- 회귀 검사 프로세스의 실제 네트워크 접근은 loopback만 허용, serial device open 차단

조회 전용 프로파일 실험:
- 실제 UDP localhost 가상 컨트롤러에 고정 query 48개 전송, 전부 해석 성공
- 최소 실제 송신 간격 0.251초 (설정 0.25초)
- 전송 목록이 고정 허용 query 목록과 ID/문자열 단위로 일치, write 0개
- 장비 응답은 Simulator 합성 응답이며 실제 Spitfire 응답 캡처가 아님
- HV ON, 양수 출력, IDN 불일치, 무응답, 연속 실패, 점유 포트, 취소,
  송신 시한 만료, trace 기록 실패, query ID를 이용한 명령문 삽입 등 검사
- GUI 점검 실패 상태에서 전체 hardware CLI를 실행했을 때 localhost 대상 수신 패킷 0개
- headless offline CLI는 의도대로 FAIL 보고서를 생성. 이를 GUI 검사 PASS로 표시하지 않음

배포 검사:
- wheel 오프라인 빌드 및 포함 pySerial로 설치 성공
- 설치된 validation CLI import / --help 정상
- wheel Python 모듈 15개와 src 내용 동일
- Windows PowerShell 래퍼 및 PyInstaller EXE는 실제 실행하지 않았음
- 파일명/버전/프로토콜/hash가 일치하지 않는 EXE를 거부하는 로직 검사
- 기존 146개 command catalogue 변경 없음
