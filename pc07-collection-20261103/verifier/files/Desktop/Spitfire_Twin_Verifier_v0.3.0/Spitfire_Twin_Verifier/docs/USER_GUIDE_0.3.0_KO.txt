Spitfire Twin Verifier0.3.0 사용·검증 범위
=========================================

A. 어떤 도구인가
----------------
XP 원본GUI와 Python 코드의 통신 증거를 수집·비교하고, 실제 Python 코드를
가상 UDP 장비에 연결해 상태 해석과 외부 펌프 소프트웨어 정책을 시험합니다.
실제 레이저로 제어 패킷을 전달하는 프록시가 아닙니다.
원본 EXE/installer와 Python 제품 코드는 변경하지 않습니다.

B. 버전 바꾸기
--------------
프로파일 선택은 표시명과 근거만 변경합니다. 실행파일이 자동 교체되지는 않습니다.
[ZIP 추가] 또는 [폴더 추가]로 실제 시험할 코드를 지정하세요.
파일 버전·명령목록·해시를 정적으로 검사합니다. ZIP 경로탈출·symlink·과대파일을 거절합니다.
새 버전의 spitfire_control API가 같으면 공통 어댑터가 시험하며,
미지원 API/명령은 미지원 또는 오류로 남습니다. 이름만 같다고 호환 처리하지 않습니다.
XP의 다른 버전은 해당 installer와 캡처 근거가 필요하며,1.6.0으로 이름만 바꾸면 안 됩니다.

[추가한 코드로 loopback 시험]은 명시적 확인 후 선택한 Python 소스를 실행합니다.
별도 프로세스는 악성코드 보안 격리가 아닙니다. 신뢰하는 프로젝트만 선택하세요.
각 시험은 새 프로세스·새 가상 장비를 사용하며 목적지는127.0.0.1뿐입니다.
일반 transport/state와 외부 모드 enable-policy를 직접 검사하지만,
GUI 전체 조작·controller polling loop·광학 동기화의 자동 검증은 아닙니다.

C. 시나리오 모델
----------------
내장12종: 정상10Hz,시드 상실/회복,펌프 부재,펌프준비 실패,트리거 누락,
중복,지터,반복률 불일치,위상차,인터록,열/유량/HV,통신 단절.
80MHz와10Hz는 편집 가능한 합성 입력 조건이며 장비 사양 보증이 아닙니다.
[모델 자체 시험]은 이벤트 상태전이와 기대 assertion만 검사합니다.
그 PASS를 프로그램 반응PASS나 실제 안전PASS로 읽으면 안 됩니다.

실제 클라이언트에 같은 자극을 주려면:
1. 장비 정지 → 이전 보고서 저장 → 캡처 초기화.
2. 시나리오와 실시간/수동 모드를 선택하고 [다음 장비 시작에 적용].
3. 가상 장비 시작 후 XP/Python 클라이언트를 연결.
4. 실시간은 각 클라이언트 첫 요청이0ms. 수동은 입력한 절대ms로 전진.
5. 두 프로그램에 같은 조작을 하고 캡처 및 GUI 관찰을 남김.
6. 정지 후 비교/보고서 저장. 서로 다른 이벤트 단계면 차이로 표시됩니다.

시나리오의 armed/inhibited는 합성 정책 상태입니다. 실제 HV 피드백이 아닙니다.
확인되지 않은 하드웨어 상태비트를 자동 생성하거나 장비를 물리적으로 차단하지 않습니다.
UDP 응답 변화는 JSON의 명시적 wire 이벤트만 적용됩니다.
예: seed 주파수1065,TDG key fault1066='4000'(HEX),COM1089='2'(decimal).
1024를 measured seed로 취급하지 않습니다.
wire_override를 제거하면 가상 장비 기본값으로 복귀합니다.
지터/위상/10Hz 펌프 펄스 상태를 TDG가 실제 어떤 비트로 보고할지는 미확인입니다.

D. XP VM 실제 시험
------------------
필요: 합법적으로 확보한XP 설치환경,정상XP VM,원본 installer,CVI runtime.
현재P04에서XP VM은 발견되지 않았습니다. 설치·라이선스·권한은 별도입니다.
XP를 인터넷/실제 레이저망에 연결하지 마세요. Host-only NIC만 사용합니다.
원본 코드에는 시작 중INT→EXT 자동쓰기 경로가 있으므로 실장비 연결 금지.

Host-only 예:
가상 장비(Win11 호스트의전용IP):10.19.70.13/24 UDP1024
XP VM:10.19.70.2/24
Python 클라이언트호스트:10.19.70.1/24
Verifier에서 이IP를 명시적으로 설정해야 합니다. 기본은127.0.0.1입니다.
전용IP를 실제 장비가 사용하는 LAN 어댑터에 붙이지 마세요.
방화벽 예외가 필요하면 해당Host-only주소/VM만 허용하세요.
본 작업은 네트워크/방화벽을 자동 변경하지 않았습니다.

검증 순서: 원본 시작→identity/초기화→조회 화면→설정/readback→각fault화면
→통신 유실→복구→종료. 패킷과 화면을 함께 남깁니다.
무조건MATCH가 목표가 아닙니다. 원본의 자동쓰기와새버전의보수적정책 차이는
의도된차이일 수 있으므로 경로와근거를 검토해야 합니다.

E. 판정
--------
PASS: 특정 테스트의독립기대값 통과(범위 확인).
MATCH: 수집된wire내용 일치. 내부GUI/물리반응 인증이 아님.
DIFFERENT/FAIL: 관측 차이 또는기대값 불일치.
UNSUPPORTED: 해당버전API/명령 기능 없음.
INCOMPLETE: 비교한쪽/시간창/캡처가 미완료.
UNVERIFIED/NOT_CHECKED: 근거부족,실행안함,물리효과미모델링.
OBSERVATION_REQUIRED: 오류주입/합성fault가 있어 프로그램 반응 관찰필요.
오류를 두클라이언트가 똑같이 무시해도 정상안전으로 판정하지 않습니다.

F. 캡처 재생과 시간창 반응
--------------------------
캡처JSONL은 원시요청/응답·출처·시간·프로파일·이벤트단계를 저장합니다.
--compare-capture로 다시 비교할 수 있습니다.
--replay-capture는loopback에서 정확히같은요청에만 기록된raw응답을 돌려줍니다.
요청을 실제장비로 재전송하지 않습니다. 원래응답지연을 재현하지도 않습니다.
--reaction-rules는 지정가상시간창 내 명령송신 require/forbid를 검사합니다.
전체시간창과양쪽클라이언트증거가 없으면PASS하지 않습니다.
예제reference/reaction_rules.example.json은 소프트웨어 요구사항 예일 뿐,
XP가그동작을해야한다는제조사근거는 아닙니다. 시험 목적에 맞게 수정하세요.

G. 아직 하지 않은 것
---------------------
XP GUI 실제실행,Windows10실행,모든원본패널 동적대조,
실제TDG/Empower/DM527 펌프/TTL/광펄스/에너지/위상 측정,
Signal/HIL 연동,별도TCP1001/RS232서비스복제,모든펌웨어프로파일.
안전인증이나실제10Hz운전가능증명으로사용하지 마세요.
