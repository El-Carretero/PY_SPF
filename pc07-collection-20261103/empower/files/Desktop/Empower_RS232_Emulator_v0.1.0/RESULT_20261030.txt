Empower RS-232 Emulator 0.1.0 — 07번 VMware XP 원본 연결 결과
시험일: 2026-10-30, KST

완료한 일
  07번 PC에 Empower 요청-응답 에뮬레이터를 구현·배치했다.
  VMware XP를 부팅하고 기존에 설치된 원본 Spitfire 프로그램을 실행했다.
  원본 프로그램과 에뮬레이터의 통신 및 화면 반영을 확인했다.

실제로 사용한 경로
  XP 원본 Spitfire (10.19.70.2:1024/UDP)
    -> 가상 SASC 어댑터 (07번 VMnet1의 10.19.70.13:1024/UDP)
    -> Empower 바이너리 TCP 전송 (07번 loopback 127.0.0.1:19200)
    -> 캡처 기반 Empower 피어

  가상 SASC/TDG/TCU/Head 부분은 합성 모델이다. 실제 SASC 펌웨어나 실제
  Spitfire 본체의 RS-232 포트를 시험했다고 해석하면 안 된다.
  별도의 --serial 모드를 구현했지만, 실제 Spitfire 본체와 직렬 케이블로
  연결하여 요청을 받은 시험은 이번에 수행하지 않았다.

화면 관찰
  MAIN, EMP, AMP, TDG, TCU 램프가 녹색.
  STOP 램프 점등, FAULT 및 RUN 램프 꺼짐, ALL SYS OK 및 BWD OK 표시.
  펌프 반복률 및 증폭기 반복률 모두 1000 Hz 표시.
  Empower Setup 창: 최대전류 25 A, 측정값 0.2 A, 초기 설정값 0 A,
  Q-switch INTERNAL 표시. 측정값 0.2 A는 캡처 템플릿의 보존값이며 실제 측정이 아니다.
  시험 중 RUN을 누르거나 가상 HV를 켜지 않았다.

설정 변경 왕복
  15:56:22 KST: 원본 GUI에 8.0 A 입력.
    XP 송신: [2003]EMP:DIODE:CURR 80.00
    바이너리 요청: 10 02 00 00 11 01 02 00 00 64 00 28 00 00 00 50 02
    바이너리 응답: opcode 0x11, 설정 current word=0x0050 (8.0 A).

  15:57:16 KST: 원본 GUI의 설정값을 0 A로 복구.
    XP 송신: [2003]EMP:DIODE:CURR  0.00
    바이너리 요청: 10 02 00 00 11 01 02 00 00 64 00 28 00 00 00 00 b2
    바이너리 응답: opcode 0x11, 설정 current word=0.

  상태 변경 응답은 합성 모델이다. 실제 장비의 14.5->12.5 A 같은 기존
  비일치 사례를 이 모델이 재현했다고 주장하지 않는다. 해당 원본 캡처를
  바탕으로 한 정확한 불일치 재생은 별도 프로파일로 확장해야 한다.

자동 시험
  Linux/Python 3.12: 19개 시험 + 11개 하위 검사 통과, 실패/스킵 없음.
  07번 Windows/Python 3.13: 18개 시험 통과.
  Linux 추가 1개는 실제 직렬 이벤트 루프를 PTY로 연결한 시험이다.
  이 PTY 시험은 19200 baud, 분할 프레임 수신, 캡처 응답 및 정상 종료를
  확인하며 실제 전기적 RS-232 케이블 시험을 대체하지 않는다.
  프레임 11개의 길이 및 가산 체크섬은 모두 검사했다.

수정 사항
  최초 화면 대조에서 반복률 변환의 10배 오차를 발견했다.
  FW1.2의 주파수 word는 0.01 kHz=10 Hz이며 원본 Spitfire의 조회값과 같은
  단위이다. 중복 변환을 제거하고 독립 회귀 시험 및 XP 화면으로 재확인했다.

검증 범위의 한계
  SASC ASCII<->Empower 바이너리 대응과 미수집 상태 변화는 추정 또는 합성이다.
  에뮬레이터가 원본 GUI를 정상 표시시켰다는 결과는 실제 펌웨어 동작과
  광출력 동작이 검증됐다는 뜻이 아니다. 현재 확보된 대표 캡처 프레임을
  사용했으며 과거 JSONL 전체 6개를 재확보한 것은 아니다.
  실제 Spitfire 본체가 보내는 RS-232 요청의 종류·순서·시간·배선 호환성은
  다음 하드웨어 연결 시험에서 확인해야 한다.
