# Native PY_SPF 1.2.1 — EXT 반복률의 공용 입력

기존 Timing 패널의 `INTERNAL AMP REP RATE` 입력칸(패널 5, 컨트롤 28)을 EXT 표시의 주파수 기준으로도 사용한다. 입력칸과 원본 UIR·DLL은 추가하거나 수정하지 않는다. 제품 표시명·설치 파일명은 1.2 계열을 유지하고, 패키지 버전으로 1.2.1을 구분한다.

## 표시와 장비 제어

- 기존 `2032 TDG:TRIG:FREQ <Hz>` 설정과 `1053 TDG:TRIG:FREQ?` 확인 경로를 유지한다.
- `EXT Pump = 유효한 1053 응답으로 확인된 주파수`이다.
- `EXT Amp = 확인된 주파수 ÷ DIVISOR`이다. DIVISOR 0의 기존 계산 규칙은 1로 취급하는 것이다.
- 10 Hz 입력이 확인되고 DIVISOR가 1이면 EXT Pump/AMP는 10/10 Hz, DIVISOR가 2이면 10/5 Hz이다.
- 주파수 확인 전이나 응답 대기 중에는 새 입력값을 적용 완료로 표시하지 않는다. 미응답·잘못된 응답·불일치 때의 기존 확인·복원 처리를 유지한다.
- Empower PRF 응답, Empower 설정 변경의 표시 갱신, DIVISOR 변경, 초기화·재연결이 이전 Empower 기반 EXT 표시를 되살리지 않도록 계산원을 일관되게 적용한다.

이 값은 사용자가 지정하고 TDG 내부 설정 조회로 확인한 **주파수 기준값**이다. BNC 외부 트리거의 실측 주파수가 아니다. 실제 외부 동기는 Amplifier Trigger Input의 신호가 담당한다. 저장된 내부 주파수와 같은 값을 공유하므로 Internal 모드를 선택하면 해당 내부 설정도 사용하게 된다.

## 변경 범위

입력 범위 10–10000 Hz, 읽기 전용·연결 준비·대기 중 재입력 제한과 장비 조회 확인을 유지한다. 모드 선택, RUN·STOP·HV·Fault/BWD Reset·CH1/CH2 지연 명령, Empower 자체 설정과 Opt-out 정책은 변경하지 않는다. XP 원본 응답 디코더·콜백의 역설계 결과와 현재 제품의 표시 정책을 구분한다.

설치는 같은 AppId·뮤텍스·바로가기·등록된 설치 경로·사용자 데이터 경로를 유지한다. 기존 Python·NI 등록·PATH·설정·네트워크 구성에 변경을 가하지 않는다.

## 실장비 기준 확인

2026-11-05 한국 시간 18:49:51–18:49:54, 01번에 연결된 SASC 1.5.0 제어기에서 기존 프로그램과 같은 UDP 명령으로 시험했다. 시작 상태는 Amplifier Trigger EXT, 저장 주파수 1000 Hz, DIVISOR 1, HV OFF, Empower Opt-out ON이었다.

`2032 TDG:TRIG:FREQ 10.00`을 한 번 전송한 뒤 `1053`은 세 번 모두 `10.0`을 반환했다. 모드 조회 `1051`은 계속 `EXT CONT 1000.0`이었다. 따라서 그 응답 뒤의 숫자를 새 주파수 확인으로 대신 사용하지 않는다. 시험 후 `2032 ... 1000.00`으로 복원했고, 전후 9개 조회 응답이 일치했다. 송신·수신은 각각 29회, 타임아웃·재시도는 없었으며 쓰기는 주파수 설정·복원 두 번뿐이었다.

이는 **패치 전 제어기의 설정 저장·반환 시험**이다. Windows 마우스 입력, 외부 TTL 수용·주파수, Pockels Cell 출력 파형, 광학 Emission을 검증한 결과로 확대하지 않는다. 원시 통신과 사용자 경로는 로컬에 보존한다.

## 패치 검증

회귀시험은 EXT 10/10 Hz·분주 후 10/5 Hz, Empower 응답에 의한 덮어쓰기 방지, 잘못된 조회·불일치·미응답·재연결을 검사한다. Windows x86 설치본의 Native 검증은 장비 소켓을 금지한 시뮬레이터에서 실행하고, EXT 표시 화면과 보고서를 보존한다. 01번 설치 검증에서는 배포 해시·버전·사용자 환경 보존과 설치된 EXE의 Native 자체 검사를 확인한다.
