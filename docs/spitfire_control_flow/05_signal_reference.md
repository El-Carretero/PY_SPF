# 5. Signal and state reference

This reference distinguishes physical inputs, controller telemetry, and software selections. **MANUAL** entries describe MAN-330A's Spitfire Pro configurations; their applicability to the user's **2005 SPTF-100F-1KHPR** remains **UNKNOWN** until the nameplate, ship report, TDG revision, and installed wiring are matched. **CODE VERIFIED** means the frozen Python implementation at commit `cebcc28490f48e9e5d4d1c2e2feef34d638244e7` implements the stated mapping. **XP/LOG VERIFIED** observations are identified separately in the report; they do not automatically validate every possible physical state.

In the tables, **fault** means a source explicitly reports/describes a fault; **inhibit** means a documented function prevents an action or amplified output. One condition can be both. **UNKNOWN** means the supplied evidence does not establish the behavior, not that no protection exists. “Continuous” identifies an operational dependency, not a measured scan frequency or firmware service interval. No commands were sent to equipment to generate this reference.

MAN-330A specifies 50 Ω, internally switchable impedance and jitter below 250 ps for the described seed synchronization input (printed 4-6; PDF 52). These values do not supply an input voltage range, complete termination arrangement, connector pinout, pulse width, or measured installed jitter. Those details are **UNKNOWN** for the target hardware. The word TTL applies to the manual's pump trigger description, not to every connector or status bit in this report.

The documented control path is computer Ethernet → TDG **10BaseT**, with the TDG **PWR SUPPLY COMM** 26-pin D-sub connected to the Empower power supply's RS-232 connector, and **LASER COMM** 26-pin D-sub connected to the head umbilical [M-4.5; M-4.6]. These communication connections are separate from the BNC timing inputs and the high-voltage cable. Pin assignments and the actual external-pump adaptation remain **UNKNOWN** (installed-pump wiring; Section 6).

### Three different uses of INTERNAL

| Selection | Source/domain | Evidence-supported statement | Unproved substitution |
|---|---|---|---|
| Empower QSW SOURCE INTERNAL | `EMP:QSW:SOURCE`; pump power-supply clock | Manufacturer describes a factory-configured internal Q-switch repetition-rate source. EXTERNAL uses the pump's rear EXT QS TRIG IN; HOLD OFF is a separate service state. | Does not establish TDG seed lock or remove a physical seed/BWD requirement. |
| TDG oscillator INT/EXT | `TDG:OSC:MODE`; callbacks and readback | Code sends distinct `INT`/`EXT` values and maps the returned text to an oscillator-mode widget. The initialization decoder can queue INT then EXT when the response lacks `INT`. | Firmware clock routing, seed-reference synthesis, and installed calibration are UNKNOWN. |
| TDG trigger INT/EXT | `TDG:TRIG:MODE`; callbacks and readback | Code sends a separate mode request and changes which trigger controls are visible. | Does not establish that a selected TDG rate creates pump photons, operates a replacement pump, or satisfies pump/seed interlocks. |

The first row is **MANUAL** [M-6.11]; the latter two are **CODE VERIFIED** [C-SIG-1; C-SIG-2; C-SIG-9]. A captured INT/EXT response can be **XP/LOG VERIFIED** for that observed state while the physical meaning beyond the code remains **UNKNOWN**. This distinction prevents an INTERNAL label in one subsystem from being reused as a master explanation for the whole laser.

## 5.4 Independent optical proof boundary

A useful evidence chain is **request → accepted device reply → decoded state → measured electrical timing → measured optical pulse**. The first three are available in software traces; none automatically proves the last two. A GUI EMISSION bar is pump-state telemetry. PD1/PD2 are BWD detector interpretations. TDG frequency is a returned measurement, and PC enable/HV readback is controller state. None alone establishes amplified output power, pulse energy, pulse duration, spectral bandwidth, beam quality, or correct capture/ejection phase.

MAN-330A recommends external power, fast-photodiode/oscilloscope, and autocorrelation measurements (printed 6-1 and 6-3; PDF 61 and 63), and explicitly lists no-output cases involving timing, interlocks, drivers, and optical alignment (printed 8-1/8-3; PDF 87/89). This report contains no independently acquired optical measurements from the user's system. Its optical-performance conclusion is therefore **UNKNOWN**, even where software state is **CODE VERIFIED** or **XP/LOG VERIFIED**.
