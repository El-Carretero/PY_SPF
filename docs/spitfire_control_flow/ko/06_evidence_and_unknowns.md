# 6. 근거, 재현 가능성, 미확인 사항

이 장은 복구한 프로그램 동작, 저장된 실장비 관측, 아직 측정하지 않은 동작을 구분한다. 기본 근거 라벨은 **CODE VERIFIED**, **XP/LOG VERIFIED**, **MANUAL**, **INFERRED**, **UNKNOWN**이다. 각 라벨은 특정 주장과 시험 범위에 적용되며, 제어기나 레이저 전체를 인증하지 않는다.

## 근거 라벨 읽는 법

| 기본 라벨 | 반드시 구분할 의미 |
|---|---|
| **CODE VERIFIED** | 인용한 현재 Python 소스에서 프로그램 동작을 확인했다. 이것만으로 장비의 실행이나 광학적 동작이 확인되지는 않는다. |
| **XP/LOG VERIFIED** | 출처가 **원본 x86 역어셈블리/에뮬레이션**, **실장비 프로그램 로그**, **과거 읽기 전용 수집 기록**, **장비를 연결하지 않은 Native 런타임 시험** 중 무엇인지 명시한다. 원본 x86 분석은 실제 XP PC 시험이 아니다. 이 라벨만으로 원본 프로그램을 Windows XP에서 실장비와 함께 시험했다고 해석하면 안 된다. |
| **MANUAL** | 문서, 개정판, 대상 모델, 인쇄/PDF 페이지를 식별한다. 다른 모델의 매뉴얼은 참고 근거이며, 검증된 SASC 펌웨어 사양이 아니다. |
| **INFERRED** | 식별한 코드, 관측 또는 매뉴얼로부터 도출한 결론이지만, 전체 인과 경로를 측정하지는 않았다. 빠진 단계를 명시한다. |
| **UNKNOWN** | 필요한 관측이나 권위 있는 사양이 없다. 시뮬레이터 결과나 빈 ACK로 이 공백을 채울 수 없다. |

[출처 레지스트리](../evidence/source_registry.json)는 `E-STATIC`, `E-EMULATED`, `E-SYNTHETIC`, `E-NATIVE-NO-DEVICE`, `E-PHYSICAL-READONLY`, `E-PHYSICAL-CONTROL-LOG`, `E-PHYSICAL-WRAPPED`, `E-MANUAL`, `E-UNKNOWN`이라는 출처 유형을 추가한다. `E-PUBLICATION-STANDARD`는 별도의 문서 형식 기준을 식별하며 장비 동작을 주장하지 않는다. 자료의 접근 가능 여부는 별도로 기록한다. 저장소에 포함된 소스나 선별 요약본은 저장소 독자가 열람할 수 없는 비공개 원문과 다르다. 원본 출처의 해시와 고정된 브랜치 기준은 [source_manifest.json](../evidence/source_manifest.json)과 [branch_baselines.json](../evidence/branch_baselines.json)에 기록한다.

### 매뉴얼 식별과 페이지 표기

`MAN-330A`는 **Spitfire Pro User Manual, 330A Rev A**이며 PDF 110페이지, SHA256은 `d9bb260827f78a2ed67477043cb3036a26b771aaf19a0c3ec9aa6649449d5e29`이다. 이 안내서에서 사용하는 페이지 예시는 인쇄 4-4 / PDF 50, 6-1 / PDF 61, 6-9 / PDF 69, 6-10 / PDF 70, 8-3 / PDF 89이다. `STD-XL`은 **XL-STD-DOC-001 xLaPPLAs Technical Publications Standards, Rev A**이며 PDF 63페이지, SHA256은 `3a59e249677683bc373a0a1f4ee35fbfb9e677310c49f778806a961654663157`이다. 문서 표현 형식을 규정하며 운용 매뉴얼이나 펌웨어 사양은 아니다.

PDF 페이지는 인쇄된 절별 페이지 번호가 아니라 파일의 첫 페이지를 1로 세는 번호이다. 원본 첨부는 프로젝트 소유자가 보관하며, 여기에는 문서 식별 정보와 제한된 기술 인용만 남긴다. 운용 매뉴얼이 있다는 사실만으로 설치된 하드웨어가 그 매뉴얼의 모델이나 개정판이라고 확인되지는 않는다. 현재 펌웨어에 관한 주장에는 여전히 일치하는 사양이나 측정이 필요하다.

## 실장비 관측과 정확한 한계

### BWD 이력: 저장된 해제 응답 없음

PC1 스캔은 보존된 두 프로그램 로그 루트 아래 JSONL 84개를 조사하고 직접 조회한 JSON 수집본 2개를 추가했다. 합성 세션, 저장 값 재생, 동일 파일 복사본, 부분 전송본, 복사한 Native 접두 자료, 기존 통신 로그와 같은 세션의 진단 표현을 제외했다. 채택한 자료는 **19개 출처의 응답 10,464행**이다. `1039 TDG:STBH?`는 10,063행, `1066 TDG:STBHFLT?`는 401행이다. 동일한 응답 반복 5행은 같은 원문 수신 기록에 속하므로 원문 기록은 10,459개이다. 이를 독립적인 신규 장비 측정 횟수라고 표현하면 안 된다.

`0x00330409`가 10,204행, `0x00334408`이 260행이다. 두 값 모두 `word & 0x300000 == 0x300000`을 만족한다. **보존된 유효 응답 중 `0x100000` 또는 `0x200000`이 해제된 응답은 없다.** 포함된 가장 이른 응답은 2026-11-02 03:13:55.059996 UTC, 가장 늦은 응답은 08:12:48.504 UTC이다. 이 양 끝 시각은 연속 관측을 뜻하지 않는다. 표본 사이에 해제됐다가 다시 래치됐지만 관측되지 않았을 가능성을 배제할 수 없다.

같은 보존 이력에는 **`2018 TDG:RESBWD` 송신 44회와 동일 태그의 빈 ACK 44회**가 있다. 대응 지연은 6–88ms이며 일반 Native 로그 42회와 범위를 제한한 실장비 진단 2회로 구성된다. 이것은 대응 응답 수신을 뒷받침하며 BWD 해제나 물리적 Reset 성공을 뜻하지 않는다. BWD 버튼은 **1039**로 디코딩하지만 버튼 콜백의 즉시 후속 조회는 **1066**이다. 1066 수신만으로 메인 BWD 버튼 입력을 새로 측정했다고 볼 수 없다. [BWD 이력, 아래 Reset 콜백 및 디코더 참조.]

필터링 전 후보에서 0값처럼 보였던 응답 1,166행은 모두 localhost 또는 시뮬레이터 메뉴 시험에서 나왔다. 다른 후보 1,257행은 이전에 기록한 값을 재생했다. 어느 쪽도 실장비가 BWD OK에 도달했다는 근거가 아니다.

### Fault Reset: 정상 ACK 중에도 STATUS는 만료될 수 있음

일반 제어 기록에서는 Fault Reset 8그룹이 우선 요청 112개를 큐에 넣었다. Reset 쓰기 32개 중 **31개를 송신하고 ACK를 받았으며**, 마지막 `2050 RESET`은 STATUS 만료 시 취소됐다. 연속한 실제 STATUS 응답 사이 간격은 41.122초였고, 약 11.117초 동안 GUI 준비 상태가 false였다. 그 구간의 저장 기록에는 UDP 오류, 쓰기 ACK 만료, 전체 재연결이 없다.

오프라인에서 1회와 8회 요청을 비교 재생해 우선 큐의 폴링 지연을 재현했다. 한 그룹은 준비 상태를 유지했지만 8그룹은 STATUS를 지연시키고 마지막 Reset을 취소했다. 이는 관측된 사례를 설명하는 프로그램 큐 경로를 뒷받침한다. USB 어댑터 고장을 입증하거나, 어댑터가 고장 날 수 없음을 증명하거나, `RESET`의 모든 펌웨어 효과를 확인한 것은 아니다.

별도로 범위를 제한한 재시험에서는 `2044`, `2049`, `2052`, `2050`을 각각 한 번 송신했다. ACK 지연은 약 13.930, 34.579, 21.427, 87.424ms였다. 마지막 쓰기 후 60.039초 관측 중 `STATUS`는 3에서 2로, `COMSTATUS`는 1에서 0으로 바뀌었고 BWD는 설정된 상태를 유지했다. 조회 재시도 4건은 모두 회복됐으며 Reset 전 2건, 후 2건이었다. 재시도를 소진한 조회 타임아웃이나 재연결은 없었다. 이를 “재시도 없음”, “모든 고장 해제” 또는 완전한 물리 출력 시험으로 바꿔 표현하면 안 된다.

### Native 읽기 전용 장시간 관측: 집계 구간을 구분

릴리스 완료 스냅샷은 **1,800.553초**이며 송신 6,816회, 매칭 응답 6,754회, 조회 재시도 62회이다. 재시도를 소진한 조회 타임아웃이나 재연결은 없었다. 이후 비공개 분석은 **1,813.567초** 구간을 다루며 송신 6,867회, 매칭 6,804회이고 스냅샷 시점에 요청 1개가 진행 중이었다. 같은 세션의 서로 다른 두 집계 구간이며 추가 독립 시험이 아니다.

뒤의 분석 구간에는 변화가 없는 1039 상태 표본 3,490개가 있다. 1066 표본 2개와 1068 표본 1개는 초기화에서 나왔다. 따라서 해당 표본에서 “관측된 BWD 전이 없음”은 근거가 있지만, “1066과 Opt-out을 30분 동안 계속 재조회함”은 근거가 없다. 읽기 전용 모드에서 장비 쓰기는 없었다. 시험한 메뉴 사례에서는 통신이 계속 진행됐으나, 모든 대화상자나 OS 이벤트 경로를 인증하지는 않는다.

## 재현 가능성과 접근 범위

원본 PE/UIR, 복구한 표, 오라클 스크립트, 합성 시험 자료, 간결한 검증 보고서는 저장소에 포함돼 있다. 저장소만으로도 이를 살펴보고 오프라인 회귀/오라클 도구를 실행할 수 있다. 예를 들어 `analysis/verify_optout_capture.py`는 소켓 생성을 금지하고 합성 예제를 비교한다. 선택 사항인 원본 코드 오라클도 API를 가로채는 x86 에뮬레이션이다. 재생을 실행해도 새로운 실장비 근거가 생기지는 않는다.

로거 오라클 14사례는 Python 비교 13사례와 원본만 확인한 파일 열기 실패 1사례를 포함한다. NI 포매터와 Windows 텍스트 모드 줄바꿈 동작은 대역 처리한다. 디코더 오라클은 선택한 최종 GUI 갱신을 비교하며 일부 파싱 보조 함수를 Python 구현과 공유한다. 이 검사는 유용한 대응 근거지만 전체 스케줄러, 콜백 순서, 센서 보정, 물리 단위의 독립적인 검증은 아니다.

비공개 원문 파일과 진단 래퍼는 레지스트리와 선별 목록에서 식별한다. 이를 저장소 첨부로 암묵적으로 취급하지 않는다. 해시는 보존한 바이트를 식별하지만, 열람할 수 없는 비공개 파일을 독자가 독립적으로 검사할 수 있게 하지는 않는다. 과거 보고서는 당시 코드와 시험 스냅샷을 설명한다. 릴리스 검증의 시험 219개와 subtest 7개는 릴리스 시점의 결과이며, 현재 문서 브랜치의 시험 개수가 정확히 같다는 보장은 아니다.

## 남아 있는 미확인 사항

| 항목 | 라벨 | 없는 근거 / 범위 |
|---|---|---|
| Wireshark 또는 NIC 수준 패킷 캡처 | **UNKNOWN** | 이 안내서에 사용 가능한 자료에는 PCAP/PCAPNG가 없다. JSONL/CSV는 프로그램 수준 UDP 근거이며 패킷 캡처 파일이 아니다. 이 자료로 펌웨어, OS, 네트워크, 어댑터 중 어디에서 손실이나 중복이 발생했는지 특정할 수 없다. |
| 실제 Windows XP에서 전체 프로그램/장비 운용 | **UNKNOWN** | 원본 x86 오라클은 에뮬레이션이며 Native Windows 10/11과 Wine/QEMU는 다른 환경이다. XP GUI 이벤트 전달과 장비 타이밍을 인증하지 않았다. |
| BWD 비트와 검출기/채널 배선의 대응 | **UNKNOWN** | 디코더는 BWD의 2비트 마스크를 확인한다. 검증된 명판, 일치하는 회로/배선 문서, 각 원시 비트를 물리 검출기/채널에 대응시키는 측정이 없다. PC1/PC2 또는 PD1/PD2 대응을 임의로 만들면 안 된다. |
| 설치된 펌웨어의 BWD Reset 조건 | **UNKNOWN** | ACK를 받았어도 비트가 계속 설정돼 있다면, 어떤 물리 전제 조건, 래치, 센서 입력, 펌웨어 규칙이 해제를 막았는지 알 수 없다. 다른 모델의 매뉴얼로 이 공백을 채울 수 없다. |
| 완전한 SASC 펌웨어 프로토콜 | **UNKNOWN** | 관측한 SASC 식별 응답과 복구한 GUI 명령은 모든 모듈 개정판의 권위 있는 펌웨어 구현/사양이 아니다. 미지원 `-99`와 빈 응답은 유효한 0 측정값이 아니다. |
| 설치된 교체 펌프와 배선 | **UNKNOWN** | 설치된 교체 펌프의 모델, 트리거/셔터/인터록 배선, 전기적 신호 수준, 고장 전파는 검증하지 않았다. 설치된 하드웨어 경로를 확인하려면 일치하는 모델·배선 문서와 감독하의 측정이 필요하다. |
| 실제 광출력과 보정 | **UNKNOWN** | 독립 광검출기, 펄스 에너지 측정, 오실로스코프 파형, 센서 보정은 이 근거에 포함되지 않는다. 버튼, LED, ACK, 숫자 표시는 그 측정을 대신하지 않는다. |
| 임의로 늦게 도착하는 동일 태그 응답 | **UNKNOWN** | 응답에는 거래별 고유 식별자가 없다. 현재 요청과 같은 태그의 지연 응답을 항상 구별할 수는 없다. 범위가 제한된 시험이 성공해도 이 프로토콜 한계가 없어지지는 않는다. |
| 관측하지 않은 구간과 Reset 과도 상태 | **UNKNOWN** | 보존 자료에는 표본 간격과 세션 공백이 있다. “저장된 해제 응답 없음”은 BWD가 모든 순간에 설정돼 있었다는 뜻이 아니다. |

## 인용 기준점

- 원본 프로그램 식별: `SPITFIRE.EXE` SHA256은 `8a87bcad1709f93358cba5f5588647999524ba8b481c2f38cc6cc82a96623e9b`이다. 고정 기준과 다른 리소스 해시는 목록에 있다. 원본 `_gextHandleReceivedMsg`의 `0x40ba24`, `_BW_reset`의 `0x40f0b7`, Reset 콜백의 `0x412428`은 실행 파일 주소 인용이며 Windows 이벤트 추적이 아니다.
- 릴리스 1.0 구현 기준: [`cebcc284` 콜백 203행](https://github.com/El-Carretero/PY_SPF/blob/cebcc28490f48e9e5d4d1c2e2feef34d638244e7/spitfire/callbacks.py#L203), [Fault 후속 순서 321행](https://github.com/El-Carretero/PY_SPF/blob/cebcc28490f48e9e5d4d1c2e2feef34d638244e7/spitfire/callbacks.py#L321), [디코더 BWD 마스크와 라벨 323행](https://github.com/El-Carretero/PY_SPF/blob/cebcc28490f48e9e5d4d1c2e2feef34d638244e7/spitfire/decoders.py#L323). 다른 고정 객체 ID는 [브랜치 기준](../evidence/branch_baselines.json)을 사용한다.
- Reset 이력 출처 기준점: 범위를 제한한 두 2018 송신은 해당 진단 통신 원문의 296/297행과 293/294행이다. 일반 Native 항목은 각각의 원문 행 번호를 유지한다. 선별 목록은 출처 해시를 식별한다. 비공개 파일의 행을 인용했다고 해서 그 원문 로그가 저장소에 포함됐다는 뜻은 아니다.
- 이 안내서의 매뉴얼 근거는 등록된 문서 ID와 인쇄/PDF 페이지 번호를 함께 인용해야 한다. 코드나 일치하는 실측이 설치된 시스템에 관한 주장을 독립적으로 뒷받침하기 전까지는 **MANUAL** 라벨을 유지한다.
