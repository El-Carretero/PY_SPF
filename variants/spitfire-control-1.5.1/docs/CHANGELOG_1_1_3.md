# 1.1.3 — 연결 확인·조회 주기·ARM 조작 개선

## 연결 확인과 Automatic polling 분리

- `Automatic polling`을 꺼도 `[1000]*idn?` 조회로 컨트롤러 응답을 확인합니다.
- 연결 확인 응답/timeout 처리가 끝난 뒤 1초 후 다음 연결 확인을 보냅니다.
  기존 polling 설정을 크게 해도 연결 확인 주기는 변하지 않습니다.
- 같은 통신 worker를 사용하며 OFF/STOP을 최우선으로 처리합니다.
  연결 확인이 예정되면 일반 대기 명령보다 먼저 처리하여 큐가 길어도
  연결 확인이 계속 밀리지 않도록 했습니다.
- 정상 응답이 오는 동안에는 Automatic polling 해제 때문에 연결·ARM이
  해제되지 않습니다. 실제 timeout/오래된 응답은 기존처럼 DISARM합니다.
  통신이 회복되어도 자동 ARM하지 않습니다.
- 연결 확인은 메인 컨트롤러 응답만 확인합니다. Automatic polling OFF에서
  개별 측정값·모듈 상태·fault를 계속 최신으로 표시하지 않습니다.
  해당 데이터가 오래되면 `—`/unknown으로 표시하며, 수동 REFRESH는 가능합니다.
- 초기 조회, 수동 조회, 설정 변경 후 readback은 체크박스와 무관하게 동작합니다.

## 온도·습도 조회 주기 2배

다음 네 항목을 두 번의 polling cycle마다 한 번 조회합니다.

| ID | 명령 | 표시 |
|---|---|---|
| 1030 | `ECU:READTEMP?` | Crystal temperature |
| 1031 | `ECU:HUM?` | Humidity |
| 1077 | `EMP:LBOTEMP?` | LBO temperature |
| 1084 | `ECU:TECTEMP?` | TEC temperature |

건너뛴 조회 slot의 시간도 유지하여 다른 항목이 더 빨라지지 않게 했습니다.
기존 cycle 설정은 유지하며 온도·습도만 그 두 배 주기를 적용합니다.
기본 설정상 1초 cycle / 온습도 2초 목표이며 실제 간격은 통신 응답 지연,
운영체제 scheduling, 수동 명령 처리 등에 따라 길어집니다.
온도 설정값이나 서비스의 온도 한계값을 수정하는 변경은 아닙니다.

## DISARM ↔ ARM 버튼

- 상단 체크박스를 상태를 표시하는 토글 버튼으로 교체했습니다.
- 기본 `DISARM` → 클릭 `ARM` → 다시 클릭 `DISARM`입니다.
- `ARM SPITFIRE` 문구 입력창을 제거했습니다. 버튼의 글자와 색으로 현재 상태를 표시합니다.
- 컨트롤러의 실제 ARM 상태를 기준으로 전환하고 화면에 즉시 반영합니다.
- 연결이 검증되지 않으면 ARM할 수 없습니다. 재연결·통신 오류·STOP/OFF 시
  DISARM으로 돌아가며, DISARM에서 대기 중인 위험 쓰기 명령을 취소합니다.
- ARM은 쓰기 명령 허용이며 레이저 ON이 아닙니다. DISARM은 쓰기 잠금이며
  레이저 OFF가 아닙니다. 기존 RUN/HV/서비스 작업의 개별 확인은 유지합니다.

## 검증

새 회귀 테스트는 다음을 확인합니다.

- 실제 localhost UDP 소켓에서 Automatic polling OFF 상태로 기존 5초 만료
  시간을 넘겨도 연결과 ARM 유지.
- 연결 확인 응답을 끊으면 DISARM, 응답 복구 후 자동 ARM 금지.
- 일반 조회가 큐에 계속 있어도 연결 확인 수행.
- 온습도 4개 항목의 조회 횟수 절반, 다른 항목 주기 유지, HV monitoring 옵션 반영.
- polling 재개 시 누락된 조회를 한꺼번에 반복하지 않음.
- 문구 입력 없이 두 번의 ARM 클릭, 미검증 연결 차단, DISARM 시 대기 쓰기 취소.
- GUI가 있는 환경에서는 버튼 종류·표시·자동 DISARM 반영도 확인.

검사 실행 결과와 검증하지 못한 범위는 `VALIDATION_1_1_3.txt`에 기록합니다.
