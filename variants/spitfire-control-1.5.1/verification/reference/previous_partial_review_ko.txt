가상 XP 원본 Spitfire 비가동 검토 — 2026-10-28 KST
검토 대상: XP GUI 1.6.0 / SASC 1.5.0 계열 패킷 / Python 1.3.4. 제품 코드 변경 없음.

완료 범위와 한계
전체 기능 검증 완료가 아니다. 실제 장비에 연결한 원본 GUI 실행은 자동 승인 검토가 거부했다. 이유는 시작 과정의 설정 쓰기가 실제 장비 상태를 변경할 수 있다는 것이었다. 실제 장비에는 읽기 전용 질의만 했고, 원본 GUI 조작은 장비용 Ethernet 어댑터를 비활성화한 뒤 Verifier에만 연결했다.
마우스 입력이 적용되지 않아 키보드로 접근 가능한 항목을 중심으로 검사했다. 단축키/포커스가 예상과 달라 전류 복원 입력이 문자열 뒤에 붙고, Tab+Up이 QSW source 대신 주파수 명령을 발생시킨 사례가 있다. 이들은 실제 장비가 분리된 시험 장치에서만 발생했으며 송수신 기록에 그대로 보존했다. 이런 입력 시도를 해당 기능의 통과로 처리하지 않았다.
RUN, HV ON, 모터 이동, TEC ON 명령은 원본의 이번 전체 송신 기록에서 발견되지 않았다. 실제 출력·동기화·보호 회로의 물리 동작은 검증하지 않았다.

추가로 확인한 Python 수정 필요 사항
1. 외부 동기화 소스 설정의 부분 적용 [재현 완료]
   UI의 외부 소스 적용은 2030 OSC EXT와 2031 TRIG EXT를 순서대로 제출한다. 빈 응답 내용이 오면 controller.py가 후속 쓰기를 취소한다.
   동일한 Python UI 메서드와 실제 UDP loopback을 사용한 시험에서 빈 응답 조건은 2030만 송신되고 OSC=EXT, TRIG=INT로 남았다. OK 응답 비교 조건은 두 명령 모두 송신되고 두 값이 EXT가 됐다.
   수정 방향: 명령별로 빈 수신 확인을 ACK/실패/실행 확인과 구분하고, 관련 readback이 목표값이 되는지 확인하는 작업 단위를 도입한다. 모든 빈 응답을 무조건 성공으로 처리하면 안 된다.

2. Empower 전류 단위 변환 누락 [GUI 송신 + 바이너리 + Python 재현]
   원본에 17.0 A 입력 → [2003]EMP:DIODE:CURR 170.00 송신.
   _slidesetcurr 0x40b00f에서 float32 10.0을 곱한다. 1007(측정 전류), 1009(설정 전류) 응답 처리기는 float64 10.0으로 나누어 표시한다.
   Python engineering_argument(2003,17.0)는 17.0을 그대로 반환한다. 원시 170.00을 읽으면 1007/1009 모두 170.0 A로 보관한다. 따라서 쓰기와 읽기 모두 원본과 10배 차이가 난다.
   수정 방향: GUI A→wire ×10, 유효한 전류 wire→A ÷10. -99 같은 무응답/오류 표시는 값으로 환산하지 않는다. Programmer의 raw 입력은 기존 raw 의미를 유지한다. Python 내장 Simulator와 Verifier도 같은 wire 단위로 맞춰야 한다.
   이 문제는 Empower 모드에 해당하며, 현재 외부 펌프 모드의 MAIN 오류 원인이라는 뜻은 아니다.

3. 연속 설정 명령과 취소 내역 [재현 및 코드 확인]
   HV setpoint 2025=3.3 kV, 2026=3.1 kV를 연속 제출한 loopback 시험에서도 첫 빈 응답 뒤 2026이 취소됐다. HV ON은 전송하지 않았다.
   현재 취소 경로는 큐를 지우지만 각 제거된 명령의 CANCEL 감사 기록을 남기지 않는다. 제출 성공/Queued 표시만으로 실제 TX나 적용 성공을 판단하면 안 된다.
   수정 방향: 작업별 queued/sent/receipt/readback-confirmed/failed/cancelled 상태, 명령별 취소 사유 및 미적용 표시.

이미 확인했던 Clear Faults 결함 재확인
원본은 이번에도 2044 → 2049 → 2052 → 2050을 송신했고 네 응답 내용이 비어 있어도 다음 명령을 계속 보냈다.
Python External 경로는 2049/2052만 보내고, Empower 경로는 2044 빈 응답에서 후속 쓰기를 취소한다. 상세 지연 전이 검증은 이전 ClearFaults 보고서의 결과를 참조한다. 이번 healthy fixture의 RESET 2050은 물리 효과가 구현되지 않았으므로 MAIN을 실제로 해소했다고 주장하지 않는다.
수정에는 전체 시퀀스, 연속 송신/조회 배치 정책, 수 초 지연 뒤의 제한된 재확인, 명령별 기록을 함께 포함해야 한다. 실제 key/interlock을 무조건 정상으로 바꾸는 수정은 이 근거에서 나오지 않는다.

Python 결함으로 분류하면 안 되는 Verifier 문제
실제 XP 캡처의 응답은 '<1045> DELAY 1 ON BWD NENA 85.82'처럼 ID 뒤에 공백이 하나 있다. 공백을 빼서 Verifier가 보냈을 때 원본은 -999와 빨간 지연 박스를 표시했다.
과거 합성 형식과 실제 공백 포함 형식을 각각 시험했고, 실제 형식의 공백을 복원한 재접속 뒤 원본은 85.82 / 990.25를 정상 표시했다. 실제 패킷과 동일한 byte를 유지해야 한다. Python의 실제 지연 문법 지원을 제거하거나 원본의 민감한 공백 처리까지 복제할 이유는 없다.
Verifier의 전류 단위도 잘못 맞춰져 있었다. 원본 1.8 A 표시는 가상 장치가 18을 반환한 결과였고, 이를 18 A로 읽으면 잘못된 결론이 된다.

통신·폴링 관찰
이번 Verifier 응답 지연은 40 ms로 설정했다. 정상 baseline에서 TDG:STBH? (1039) 요청 간격 중앙값은 0.125 s, 1015/1021/1030/1065는 약 1.86 s였다. 이는 원본의 이번 가상 환경 측정값이며 실제 장비의 허용 최대 빈도가 아니다.
COMSTATUS(1089)는 일반적으로 매 주기 균등 폴링되지 않았다. startup/Active Faults/관련 갱신 경로의 요청이므로 소수 표본의 중앙값을 주기라고 해석하지 않는다.
모든 응답을 끊자 원본은 MAIN 연결등을 끄고 'Remote system not responding, click OK to retry' 창을 띄웠다. 응답을 되살리고 15초 기다려도 창은 남았으며 OK를 누른 뒤 재접속했다.
재접속 초기화에서도 2047 LBOBREAK 1, 2030 INT → EXT 쓰기가 관찰됐다. 자동 재접속이 단순 조회만 한다고 가정하면 안 된다. Python 재접속 정책을 고칠 때 출력/모션을 자동 복구하지 않고 설정 재전송 여부를 명시해야 한다.
MAIN 연결등의 수신 생존 여부와 COMSTATUS fault bit는 별개의 정보다. 이번 결과는 MAIN fault를 무조건 Empower fault로 치환할 근거가 아니다.

검사 범위
- 원본 실행, 초기 조회/자동 설정 쓰기: 확인.
- Main 통신등·전류·온도·지연·반복률 표시: 일부 정상/오류/복구 조건 확인.
- File Exit, View 네 창, Help 버전 창: 열기/닫기 확인.
- Empower current: 17 A 입력과 wire 170 확인. 되돌리기 입력 실패도 기록.
- Q-switch frequency: 1100 Hz에 해당하는 wire 110 송신 관찰. 명시적 전체 범위/경계값 시험은 미완료.
- Active Faults: healthy 화면과 Clear Faults 네 명령 순서 확인. 모든 fault bit 조합은 이번에 재시험하지 않음.
- Timing and High Voltage: 창과 표시 확인. divisor, 모든 채널 값/enable/BWD, HV setpoint, operation mode 등 각 컨트롤의 변경·복원은 미완료.
- Temperature Control: 온도·습도·TEC 표시 확인. 서비스 설정/TEC 토글은 미시험.
- Empower QSW source/pulse width, motor speed, Programmer, Empower Service, Compressor service, opt-out/override: GUI 전체 기능 시험 미완료.
- 장시간 안정성, 패킷 중복/순서 변경, 모든 입력 경계/오류 조합: 미시험.
- 실제 하드웨어 설정 쓰기, 실제 펌프 동기화, HV·레이저·모터 가동: 미시험.

다음 작업 순서
A. 실제 장비에서 원본이 시작할 때 수행하는 설정 쓰기를 포함한 비가동 검증 범위를 명시해 승인받는다. 필요한 실제 시험은 초기값을 보존하고 발진/HV ON/모션 없이 조회·리셋·복원 가능한 설정을 하나씩 비교하는 것이다.
B. Verifier의 byte 형식·전류 단위부터 보정해 원본과 동일한 기준으로 시험한다.
C. Reset와 명령 완료 판정, 외부 source 두 단계 적용, 전류 단위를 수정하고 회귀 시험한다.
D. 아직 미검증인 GUI 기능은 별도 체크리스트로 완료한다. 현재 결과만으로 전체 기능 검증 완료를 선언하지 않는다.
